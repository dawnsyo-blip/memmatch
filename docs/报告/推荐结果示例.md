## 二、推荐方案

记忆库都装在您的 Windows 电脑上：
- 手机用 ChatGPT App 的 Remote 操控电脑上的 Codex，Codex 通过 MCP 读写记忆
- 自建前端也连同一个记忆库，多端共用一份
- 电脑需要一直开着

### 方案一：最贴合“分轻重、留情感”｜Ombre Brain

| | |
|---|---|
| 为什么推荐 | 高情绪强度的记忆衰减更慢；未解决、情绪强烈的记忆权重更高，会在对话开头自动浮现。正好对上您最排斥的“轻重不分”，以及“情感重的要留着” |
| 怎么接 | MCP，Codex 可以直接添加。Windows 上用一键启动脚本（只依赖 Python），不一定要装 Docker |
| 费用 | 向量化可以用 GLM 等模型的接口（每月几元），也可以用本地 Ollama 的 bge-m3（0 元） |
| 能看能改 | 每条记忆是一个 Markdown 文件，可以直接在 Obsidian 里浏览编辑；另有网页面板，可以钉选 |
| 不足 | 没有“先审核再入库”：记忆由 Agent 直接写入 |
| 可以二改的地方 | ① 零代码：在 Codex 的 `AGENTS.md` 里加一条“写入记忆前，先列出候选内容等我确认”；② 动代码：给写入工具加一个“待确认”状态，确认后才进入记忆桶 |
| 项目情况 | MIT 许可，中文项目，约 1400 星，2026-09 仍在更新 |

### 方案二：最贴合“先审核再入库”｜lean-memory

| | |
|---|---|
| 为什么推荐 | 合并近似记忆、降级旧记忆这类整理操作，都要您批准才生效（批准、保留、改完再批准、提升为核心）。会遗忘也会归档，排序看相关度、新旧和重要性，召回后还会重排 |
| 怎么接 | MCP。审核在网页控制台的 Review 页完成，不依赖 Claude Code |
| 费用 | 免费，用本地模型；首次要下载约 2GB 模型 |
| 不足 | 不处理情绪；文档没写中文效果（嵌入模型是 Qwen3，中文应该可以，建议先试） |
| 可以二改的地方 | README 公开了打分公式：0.6×相关度 + 0.2×新旧 + 0.2×重要性。给记忆加一个“情感强度”字段，在公式里加一项，就能实现“情感重的记得久” |
| 项目情况 | Apache-2.0，43 星，2026-08 有更新；维护者少，适合愿意自己动手的用户 |

### 方案三：按“生成—演化—检索”组合｜Ombre Brain ＋ Machine Studio ＋ 写入审核规则

| 环节 | 用什么 | 做什么 |
|---|---|---|
| 生成 | Codex 的 `AGENTS.md` 规则 | 写入前先列出候选，您确认后才写。技术内容（项目进度、部署参数、命令）写进 Machine Studio，生活和情感内容写进 Ombre Brain |
| 演化 | Ombre Brain | 情感记忆按情绪强度衰减、归档，“未解决”的记忆权重更高 |
| 演化 | Machine Studio | 技术记忆不参与情绪衰减；过期的方案、作废的端口号可以真删（Ombre Brain 是软删除，删掉的还会在搜索里冒出来） |
| 检索 | Ombre Brain | 向量加关键词召回，权重池让重要的先浮现 |
| 检索 | Machine Studio | 按项目精确搜索、看项目时间线，不会被情感记忆淹没 |

- **为什么这样搭**：Machine Studio 的作者说明了它就是为配合 Ombre Brain 设计的，把技术记忆从情感记忆里拆出来。您以工作续接和编程为主，这样拆开以后，技术细节不会挤占重要的生活记忆，反过来也一样。
- **注意**：
  - 两个都是 MCP 服务，Codex 里要添加两个
  - Machine Studio 星数很少（14），算早期项目
  - 审核环节靠提示词规则，Agent 偶尔可能不遵守。要严格执行的话，按方案一的二改方法加“待确认”状态

## 三、模拟填写发现的问题

### 已在问卷 v4 里修改

| 问题 | 怎么发现的 | 改法 |
|---|---|---|
| “用手机远程操控电脑上的 Agent”没有对应选项 | 你提出 DeepSeek Harness，核实后发现 Claude App 的 Remote Control、ChatGPT App 的 Remote 也是这种用法 | 第 3 题新增选项 |
| Kelivo 和酒馆合在一个选项里 | 给 Kelivo 用户推荐了只能装在酒馆里的扩展 | 酒馆单独列出 |
| “程序化接入”涵盖十几种 Agent | 给 Codex 用户推荐了只能装在 OpenClaw 里的插件 | 新增第 3a 题，问用的是哪个 Agent |
| 第 4 题第二项和第 5 题重复 | 第 4 题选第一项、第 5 题又选“电脑”，结果和第二项完全一样 | 第 4 题只问“单入口还是多入口” |
| “多端共用”把文档没写的也排除了 | 示例用户的结果里，Magnemo、lean-memory 等“先审核”做得最好的项目全被排除 | 只排除明显只能在一处用的项目，写明能多端共用的加分 |
| 订阅套餐约 140 元，和预算“10 元以内”看起来矛盾 | 第 17 题勾订阅、第 18 题选 10 元 | 订阅“已经在付的也算”，预算只算为记忆库新增的花费 |

### 还需要你决定的

1. **只用官方 App、又只想点几下的用户，库里没有合适的项目。**
   - Claude App 用户放宽到“能照着教程敲命令”后，有 MemHeaven（部署在自己的 Cloudflare 免费账号）和 mcp-memory-service 两个
   - DeepSeek、智谱官方 App 的用户，在这条路上找不到能用的记忆库
   - 我的建议是结果页显示“放宽哪一条就有几个选择”，并介绍其它入口（遥控电脑上的 Agent、API 客户端）。已写进问卷 v4 的跨题规则，要不要这样做，你定
2. **只有手机、预算 0 元、想直接用自带记忆应用的新手，只剩 1 个结果（Utsuwa）。** 自带记忆的应用大多要装在电脑上。是否接受这类用户结果很少，还是在结果页引导他们考虑 Kelivo 这类客户端？
3. **随机答卷中还有 12% 推荐为空。** 几乎都是上面第 1 种情况，或者“遥控电脑上的 Agent”配上“只想点几下”这种本身矛盾的组合。后者按跨题规则提示用户再确认即可。

### 选项是否穷尽

模拟中没发现明显遗漏。有两处值得留意：
- **第 1 题**：没列 Kimi、通义千问、豆包等国产模型，目前靠“其它”兜底。它们的官方 App 也接不了外部记忆，处理方式和 DeepSeek 一样
- **第 7 题**：去掉“跨应用做事”以后，用 Agent 操作日历、邮件等的用户只能选“其他”。不过这类需求和记忆关系不大，影响很小
